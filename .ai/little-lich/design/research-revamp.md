# Research revamp

Based on your real research data (`data/source/research.json`, 78 nodes in 4 tomes) and the refined, structured version in `data/refined/research/`. This replaces the research design in the design doc and in `phases/phase-07-research-manager.md`. Mockup: `ui-reference/images/03-research.png`.

## What research is in this game
Research is how the player **unlocks** things and **upgrades** things permanently. It is the main progression gate for the whole game:
- Unlocks units (18 units from 14 nodes), spells (10), Workshop buildings (5: Infuser, Storage, Transmuter, Soul Well, Undead Market), and features (summoning, cascading transmute, summoning gear recipes).
- Raises limits: max necromancers (10 nodes), barracks caps, army slots, summon slots, research benches, unit level caps, building level caps, Insight.
- Improves efficiency: building output, summoning, transmuting, research speed, spell power, costs.
- Everything is automated by **necromancers working at research benches**. No resources are spent on a node. A node costs **work** and takes time.

Because research unlocks the Workshop buildings and units, the rest of the UI grows as the player researches. Nothing locked is drawn anywhere (see below).

## Tomes
| Tome | Nodes | Roots at | Role |
|---|---|---|---|
| Necromancy | 33 | Summoning | Necromancers, summoning, skeleton line, Soul Well, Undead Market, army |
| Infusion | 27 | Basic Infusion | Infuser, Storage, Transmuter, spells, wisps, mana efficiency, benches, Insight |
| Crypt Magic | 9 | Necro Management | Crypt units (spider, ghoul, spirit, priest), necromancer speed and room |
| Spider Sorcery | 9 | Web Slinger | Spider units, web and poison spells, armour |

- Each tome has exactly one root. There are no links between tomes (no node requires a node from another tome).
- **Visibility rule:** a tome appears in the list only when found. A node appears only when every node it requires is researched. Researched nodes stay visible. There are no dimmed or locked nodes or tomes. (Setting `reveal_mode`: `available_only` default, or `show_locked` for a debug view.)
- **v0.1 scope (proposal):** Necromancy and Infusion. Infusion is needed because it unlocks the Infuser, Storage and Transmuter, which the Workshop depends on. Crypt Magic and Spider Sorcery ship disabled. This supersedes "Necromancy 1 only" in phase 7. How tomes are found is not in the data; for v0.1 start with Necromancy owned and grant Infusion after the first Graveyard clear (placeholder).

## Node model
Each node (JSON, `data/refined/research/<tome>.json`):
```json
{
  "id": "dark_recruitment",
  "tome": "necromancy",
  "name": "Dark Recruitment",
  "description": "+10 max necromancers. Necromancers cost 25% less to summon.",
  "requires": ["soul_harvesting"],
  "kind": "unlock",            // "unlock" (one-off) or "upgrade" (repeatable, has max_level)
  "work": 75,                  // research work needed (was UnlockCost)
  "max_level": 100,            // upgrade nodes only
  "work_growth_per_level": 1.15, // upgrade nodes only, placeholder
  "layout": { "x": 0.75, "y": 2 },
  "icon": "...", "icon_large": "...",
  "effects": [ ... ]
}
```
- **Unlock nodes** are researched once. Shown as circles.
- **Upgrade nodes** (21 of them, `MaxLevel` 2 to 999; the two Research Assistance nodes have max level 1 and are treated as one-off) can be researched many times. Shown as rounded squares with a level badge (`0/100`). Each level costs `work x growth^level` (placeholder 1.15; the source data only has one cost per node and all but one are a placeholder 250).
- `layout` replaces the old `Position`, which was unfinished (41 nodes at [0,0], many overlaps). The new layout is generated by layering (y = longest requirement chain) and ordering within each layer; adjust by hand later.
- `Next` is gone. It is derived from `requires`.

## Effects (structured)
All 78 nodes now have structured effects, so the game can apply them. Four effect types cover everything:

| Type | Meaning | Example |
|---|---|---|
| `unlock` | Reveals a thing. `kind`: `unit`, `building`, `spell`, `feature`, `recipes` | `{ "type":"unlock","kind":"building","id":"infuser" }` |
| `modify` | Changes a stat. `stat`, `op` (`add`, `mul`, `set`), `value`, optional `target`, `per_level`, `unit` | `{ "type":"modify","stat":"max_necromancers","op":"add","value":10 }` |
| `trigger` | Runs on an event | Necrotic Harvest: on `necrotic_blast` hit, give 1 soul. Spider Blood Coating: 5% on ally hit to poison for 5 |
| `chance` | A random bonus | Forge Master: 1% per level to make an extra sword, staff or bow when transmuting |

`per_level: true` means the value applies once per level of an upgrade node (for example `+0.05%` efficiency per level).

Stats used (from the data, all handled by the `LichManager` modifier system or the owning manager):
- **Capacity:** `max_necromancers` (flat, per level, x2 for Dark Legion and Magical Efficiency for the Mana Well), `workshop_necromancer_room`, `barracks_cap`, `army_slots`, `summon_slots`, `research_benches`, `transmuter_stations`, `unit_level_cap`, `building_and_node_level_cap`.
- **Cost and speed:** `necromancer_summon_cost`, `necromancer_tick_time`, `cost` (bones, skeleton units), `spell_cost`, `research_efficiency`.
- **Output and efficiency:** `efficiency` (Mana Well, Infuser, Soul Well, Transmuter), `output`, `mana_efficiency`, `mana_per_tick`, `summoning_efficiency`, `necromancer_efficiency`, `infuser_elemental_per_mana`, `sell_price`.
- **Combat and spells:** `unit_atk`, `max_hp`, `spell_damage`, `spell_healing`, `spell_power`, `buff_debuff_duration`, `insight`.
- **Other:** `soul_harvest_rate`, `click_resource` (Mage Hand), `transmute_free_chance`.

`target` narrows a modifier (`mana_well`, `mana_well_and_infuser`, `skeleton_units`, `all_units`, `workshops_and_benches`). The modifier system needs a `target` filter. Stacking order is an open question (see below).

## Benches and work
- A **bench** works one node (or unit level, see below) at a time. The player assigns necromancers to a bench.
- **Work per tick** = `(1 + 0.5 x necromancers) x 1.1^(bench level - 1) x research efficiency` (**placeholder formula**). A node completes when its accumulated work reaches `work`.
- Time shown in the UI = `work / work per tick x tick length`.
- Number of benches: starts at 1 or 2 (decide), +1 from Research Assistance 1 and +1 from Research Assistance 2.
- Bench level: upgraded with coin and mana. Costs come from `build.json` (`ResearchBench`): level 1 to 5 base 50 coin / 150 mana, x2.3 and x2.1 per level, then four more tiers up to level 20.
- Max necromancers per bench comes from capacity effects (Necro Capacity, Dark Empowerment, Summoning Space).
- Necromancer count can reach very large numbers if the scale decision (see audit) goes that way, so show abbreviated counts and a stepper plus the Assign by selector.
- **Offline:** work is batched like everything else. Completing a node offline applies its effects in order and shows in the away recap.

### Unit research (open decision)
`units.json` has `LevelUp.Research` (for example 1,500 for a Wisp, 3,000 for a Skeleton) and `Necrotic Evolution` says "Unlock unit research up to level 5". This implies **unit level-ups are research jobs on the same benches**. Proposal: a bench job is either a node or a unit level. The Unit Builder/Barracks starts a job; the Research page shows it on the bench. Needs your confirmation.

## How other systems use research
- **UnlockManager (new, small):** holds the set of researched node ids and levels. Everything else asks it "is X unlocked?". Workshop building list, Summoning Circle unit chooser, Spell Book, Unit Builder and the resource list all read from it. This is how "locked things never appear" works.
- **Workshop:** Infuser (Basic Infusion), Storage (Mana Storage), Transmuter (Transmute), Soul Well (Soul Well), Undead Market (Undead Market). Mana Well and Summoning Circle are available from the start (Summoning also gated by the `summoning` feature).
- **Units:** each unit has `unlock_research`. The Summoning Circle chooser shows units whose research is done.
- **Modifiers:** `modify` effects register as modifiers in the `LichManager` (or the owning building), with `target` and `per_level` multiplied by the node's level.
- **Saves:** store researched node ids, levels, bench jobs, progress and bench levels. Never store effects.

## Open decisions
1. **Scale of numbers** (audit item 7): necromancer max, research work, and bench rates all depend on it.
2. **Work per tick formula** and the starting number of benches.
3. **Upgrade node cost growth** (`work_growth_per_level`), and what the `TimeMultiplier: 2` on Mage Hand 1 means (assumed: doubles the work needed).
4. **Stacking:** several nodes cut summon cost (Dark Recruitment -25%, Dark Efficiency -50%): additive (-75%) or multiplicative (-62.5%)? Refined data assumes multiplicative `mul` values; confirm.
5. **Unit level-ups as research jobs** (above).
6. **How tomes are found** (v0.1 placeholder given above) and whether Crypt Magic and Spider Sorcery are in v0.1 (proposal: no).
7. **Insight vs Focus** naming (data uses both for the same stat; effects use `insight`).
8. **Reveal rule:** nodes appear only when their requirements are done. Confirm you do not want to see the next layer dimmed (a common request in idle games).

## Implementation (v0.1, done)
**Code:** `Scripts/Crypt/Research/Research.cs` (engine, one class per tome), `Scripts/Content/Definitions/ResearchDefinition.cs` (tomes, nodes, effects, bench), `Scripts/Core/StatTargets.cs` + `StatSheet.GetFor` (target filter), `Scripts/Crypt/ResearchStats.cs` (room, efficiency, caps, costs), `Scripts/Crypt/PassiveIncome.cs` (soul harvest), `UI/Pages/ResearchPage.cs` (image 03). Tests: `tests/LittleLich.Tests/ResearchTests.cs`.
**Data:** generated by `.ai/little-lich/data/tools/convert-research.js` from `data/refined/` into `littlelich/Data/research/` (necromancy, infusion, tomes, bench) and `littlelich/Data/units/` (bases, player_actions). Edit the refined files and re-run; do not hand-edit the generated ones. Mappings: `storage` -> `magical_storage`, `coin` -> `gold`.

### Decisions taken (placeholders, change freely)
- Scale: the data's numbers. Base max necromancers 5 (old necromancer `Max`), research raises it. Necromancer costs 50 mana + 25 souls.
- Benches: 1 at the start, 2 necromancers each; work per tick = (1 + 0.5 x necromancers) x 1.1^(bench level - 1) x research efficiency. An empty bench still works 1 per tick, so the opening is: research Summoning (4) and Soul Harvesting (7), click the Mana Well, click the circle.
- Bench levels: one level for all benches, costs from the old `build.json` ResearchBench tiers, max 20 (+ level cap research). Rounding is 2 significant figures, halves up, decimal-correct (fixes the audit's 23 rounded-down cells).
- Upgrade nodes: work x 1.15^level; Mage Hand's `time_multiplier` 2 doubles its work. An upgrade node keeps levelling on its bench until max; one-off nodes free the bench (leftover work lost). Cancelling keeps progress.
- Stacking: `mul` effects multiply (summon cost 50 x 0.75 x 0.5 = 18.75, rounded up to 19). `set` takes the highest value, then adds and muls apply.
- Tomes: Necromancy owned at the start, Infusion granted the first time the Graveyard is cleared. Crypt Magic and Spider Sorcery are not loaded.
- Bench jobs: click an available node to start it on the first free bench, or drag it onto a bench. Dropping on a busy bench swaps (the old node keeps its progress); dropping a researching node on another bench moves it with its progress (`ResearchManager.Place`).
- Reveal: `show_all` (changed at the user's request, replacing the brief's `available_only`): every node of a found tome is drawn so the player can plan ahead; nodes still waiting on requirements are dimmed with dashed lines, and the hover card names what they need. Tomes still appear only when found. `ResearchManager.Reveal = AvailableOnly` brings back the old rule. The tree opens centred on the reachable nodes at a readable zoom.
- `insight` maps to the lich stat `max_insight`. Research XP: work x 0.1 to the tome's skill (Necromancy, Magic); the data has no XP.
- Unit level-ups as bench jobs: deferred.
- Units: the 10 fighting bodies from the old data replace skeleton/zombie/bone archer/wisp. One attack each: value = ATK, cooldown = SPD seconds; AOE hits the front (no area damage yet), Healer heals the weakest ally. `summon_required` 5 (golem 10) is a placeholder. Skeletons keep weapon/armour slots for the Unit Builder; wisps have none.
- Sword, bow and staff are new materials made by three Transmuter recipes (group `summoning_gear`, opened by Summon Gear). Their inputs are placeholders.
- Workshop: Mana Well open; Summoning Circle opens with the `summoning` feature; the rest with their unlock nodes. Locked buildings are not drawn, take no staff and do not tick. The circle puts necromancers in slot 1 when research first opens them.
- Old saves: research from the old tree is dropped (fresh trees); bench staff above the new room go back to the free pool.

### What effects do in the game now
- **Applied:** unlock unit / building / recipes / feature `summoning`; `max_necromancers` (global, and room for buildings and benches), `workshop_necromancer_room`, `summon_slots`, `necromancer_summon_cost`, `cost` (skeleton units), `research_benches`, `research_efficiency`, `necromancer_efficiency`, `efficiency` / `output` (Mana Well, Infuser, Soul Well, Transmuter, incl. per-necromancer), `mana_efficiency`, `mana_per_tick` per necromancer, `summoning_efficiency`, `infuser_elemental_per_mana`, `sell_price` (bones), `click_resource`, `building_and_node_level_cap`, `insight`, `soul_harvest_rate`.
- **Stored, no consumer yet:** spell unlocks and `spell_*`, `buff_debuff_duration`; `barracks_cap`, `army_slots`, `unit_level_cap`, `unit_atk`, `max_hp`; `necromancer_tick_time`; `transmuter_stations`, `transmute_free_chance`; feature `cascading_transmute`; triggers (Necrotic Harvest) and chances (Forge Master), listed by `ResearchManager.ActiveEffects`.
